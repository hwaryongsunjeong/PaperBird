# /ticket — 후보 티켓 만들기

요청: `$ARGUMENTS`

양식의 기준은 `docs/conventions/TICKET.md`다. 먼저 읽고 그대로 따른다. 라벨 규칙은 `docs/BOUNDARIES.md` §1.

## 1. 후보 나누기
1. 요청을 **티켓 하나 = PR 하나로 끝낼 수 있는 단위**로 나눈다. 크기가 L이면 나눌 수 있는지 먼저 검토한다.
2. 각 후보에 TICKET.md §4의 모든 섹션을 채운다. 사람이 말하지 않은 내용(특히 `수용 기준`, `범위 밖`)은 추측해서 채우지 말고 **질문 목록**으로 모아 한 번에 묻는다.
3. 메인 라벨 1개와, 다른 트랙이 엮이면 서브 라벨을 제안한다.

## 2. 겹침 확인
후보마다 다음을 찾는다.

```bash
gh issue list --state open --limit 200 --json number,title,labels,body
```

- **비슷한 작업**: 제목·범위가 비슷한 열린 이슈 (승인된 티켓과 다른 사람의 `candidate` 모두)
- **같은 파일**: `예상 변경 영역`이 겹치는 열린 이슈

## 3. 확인받기
다음 표를 보여준다.

| # | 제목 | 라벨 | 크기 | 비슷한 이슈 | 파일 겹침 |
|---|---|---|---|---|---|

- 비슷한 이슈가 있는 후보는 "기존 #N에 댓글로 합치기 / 새로 만들기"를 묻는다.
- 파일이 겹치는 후보는 `관련 이슈`에 그 번호를 적는다.
- **사람이 확인하기 전에는 아무것도 만들지 않는다.**

## 4. 생성
확인된 후보만 만든다.

```bash
gh issue create --title "[<메인>] <제목>" --label "<메인>,candidate[,sub:<트랙>]" --body-file <파일>
```

- "기존 이슈에 합치기"로 정한 후보는 `gh issue comment <N> --body-file <파일>`로 내용을 보탠다.
- 프로젝트 자동 추가로 보드에 `Backlog`로 들어간다. 들어가지 않았으면 직접 추가한다.
- 보드의 `Size` 필드를 본문 크기(S/M/L)와 같게, `Iteration`을 다음 주로 지정한다 (`tracks/fullstack/docs/workflow.md` §2 "필드 바꾸는 명령"). 실패한 단계는 보고에 적는다.
- 라벨이 저장소에 없어 실패하면 만들지 말고 알린다.

## 5. 보고
- 만든 티켓 링크, 합친 이슈, 건너뛴 단계를 보고한다.
- "금요일 16:00까지 만든 후보는 팀장 승인(`/triage`) 후 월요일부터 작업"임을 알린다.
