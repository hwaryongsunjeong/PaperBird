# 스킬 스택

> 저장소의 모든 슬래시 명령(skill)을 등록·관리하는 목록이다. **여기 등록되지 않은 스킬은 만들지 않는다.**
> 스킬은 루트 `.claude/skills/<이름>/SKILL.md`에 두며, 이 폴더는 `harness` 경로다 (추가·수정·폐기 = `harness` 이슈 + 팀장 승인).

## 1. 상태 정의

| 상태 | 의미 | `SKILL.md` |
|---|---|---|
| `요청됨` | 트랙이 필요하다고 요청함. 목적·입출력 미확정 | 없음 |
| `초안` | 명세가 정해지고 `SKILL.md`를 작성함. 실제 작업에 써 보는 중 | 있음 |
| `운영` | 팀이 실제 작업에 쓰는 중 | 있음 |
| `폐기` | 더 이상 쓰지 않음. 폴더 삭제 후 이 표에는 이력으로 남김 | 삭제 |

## 3. 새 스킬 등록 절차

1. 트랙 멤버가 `harness` 이슈를 열고 아래 내용을 적는다.
   - 이름, 담당 트랙
   - 목적 (한 문장)
   - 언제 쓰는가
   - 입력 (`argument-hint`)
   - 단계
   - 출력과 기록 위치 — BOUNDARIES의 해당 트랙 범위 안이어야 함
   - 모델 자동 호출 허용 여부 — 모드 전환·되돌리기 어려운 작업은 금지 (`disable-model-invocation: true`)
2. 이 표에 `요청됨`으로 추가한다.
3. 명세가 승인되면 `SKILL.md`를 작성하고 `초안`으로 바꾼다.
4. 실제 작업에서 써 보고 문제가 없으면 `운영`으로 바꾼다.

## 4. 작성 규칙

- **이름 충돌 금지**: 스킬은 루트에 모이므로 이름이 저장소 전체에서 하나여야 한다. Claude Code 내장 명령(`/status`, `/review`, `/init`, `/help`, `/config` 등)과 같은 이름도 쓰지 않는다.
- **트랙 표시**: `description` 맨 앞에 `[트랙]`을 붙인다 (예: `[security] ...`).
- **수정 범위**: 스킬은 담당 트랙의 BOUNDARIES 범위 밖 파일을 쓰지 않는다.
- **공통 규칙 유지**: 실행하지 않은 검사를 통과로 보고하지 않는다. 머지하지 않는다. 하네스 파일을 직접 수정하지 않는다.
- **참조 문서**: 트랙 공통 설정값(명령, 라벨, 경로)은 스킬마다 반복하지 않고 트랙 참조 문서 한 곳에 둔다 (fullstack의 `workflow.md`처럼).
