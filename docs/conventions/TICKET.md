# 티켓 컨벤션

> 모든 티켓(GitHub Issue)은 이 문서의 양식을 따른다. 사람이 웹에서 만들든, AI가 만들든 같다.
> Claude Code에서는 `/ticket` 스킬이 이 문서를 읽고 양식대로 만든다. 다른 AI를 쓴다면 이 문서를 붙여 넣고 "이 양식대로 만들어"라고 요청한다.

## 1. 역할 분담

- **GitHub Issues** = 티켓 자체 (제목, 본문, 라벨, 번호)
- **GitHub Projects** = 티켓을 모아 보는 보드 (Status, Iteration)
- Projects 보드에서 바로 추가한 **Draft 카드는 티켓이 아니다.** 이슈 번호·라벨이 없어 스킬이 읽지 못하고 PR과 연결되지 않는다. 카드 메뉴의 "Convert to issue"로 이슈로 바꾼다.

## 2. 주간 흐름

| 언제 | 누가 | 무엇을 |
|---|---|---|
| 평일 ~ **금요일 16:00** | 팀원 각자 | 다음 주 작업을 후보 티켓으로 만든다 (`/ticket`) — `candidate` 라벨 |
| 금요일 16:00 이후 | 팀장 | 후보를 승인·병합·보류·반려한다 (`/triage`) |
| 월요일 | 팀원 각자 | 승인된 자기 티켓을 확인하고 작업을 시작한다 |

- **`candidate` 라벨이 붙은 티켓은 작업하지 않는다.** 승인되면 `candidate`가 떨어지고 Projects Status가 `Ready`가 된다.
- 보드 Status 흐름: `Backlog`(후보) → `Ready`(승인) → `In progress` → `In review` → `Done`. 승인됐지만 막혔으면 `Blocked`.
- 보드 `Iteration`(1주, 월요일 시작)은 승인 시 다음 주로 지정된다.
- 주중 예외는 없다. 작업 중 새로 생긴 일(스킬이 만드는 후속 이슈 포함)도 모두 `candidate`로 만들고 다음 금요일에 승인받는다.
- 승인된 티켓을 고칠 점이 있으면 이슈 댓글로 남기고, 수정은 팀장이 한다.

## 3. 제목

`[<메인 라벨>] <무엇을 하는지 한 줄>`

- 예: `[fullstack] 칸반 보드 카드 컬럼 이동`, `[security] 보고서 API PII 마스킹 적용`
- 동사로 끝나는 짧은 명사구. "~하기", "~작업" 같은 군더더기는 빼고, 마침표는 붙이지 않는다.

## 4. 본문 양식

```markdown
## 배경
<!-- 왜 필요한가. 한두 문장 -->

## 범위
<!-- 이번 티켓에서 하는 것 -->
- 

## 범위 밖
<!-- 헷갈릴 수 있지만 이번에 하지 않는 것 -->
- 

## 수용 기준
<!-- 테스트로 확인할 수 있는 문장 -->
- [ ] 

## 예상 변경 영역
<!-- 건드릴 경로·파일. 다른 티켓과의 충돌 확인에 쓴다 (예: apps/web/app/board/**, apps/api/src/report/**) -->
- 

## 크기
<!-- S: 반나절 이하 / M: 1~2일 / L: 3일 이상 — L이면 나눌 수 있는지 먼저 검토 -->
S | M | L

## 관련 이슈
<!-- 선행·연관 이슈, 상위 이슈. 없으면 "없음" -->
- 
```

- `범위`, `범위 밖`, `수용 기준`, `예상 변경 영역`, `크기`는 필수다. 비어 있으면 승인하지 않는다.

## 5. 라벨

| 라벨 | 개수 | 값 |
|---|---|---|
| 메인 라벨 | 정확히 1개 | `fullstack` / `infra` / `security` / `contracts` / `harness` |
| 서브 라벨 | 다른 트랙이 엮인 경우에만 | `sub:fullstack` / `sub:infra` / `sub:security` |
| 상태 | 새 티켓은 항상 | `candidate` |

- 예: 백엔드 기능 + 보안 엮임 → `fullstack` + `sub:security` + `candidate`
- 자세한 규칙: [BOUNDARIES §1](../BOUNDARIES.md)

## 6. 만들기 전 확인

- 열린 이슈와 다른 사람의 후보 중 **비슷한 작업**이 있으면 새로 만들지 말고 기존 티켓에 댓글로 내용을 보탠다.
- **같은 파일을 건드리는 티켓**이 있으면 `관련 이슈`에 적어 둔다. 팀장이 승인할 때 순서를 정한다.
