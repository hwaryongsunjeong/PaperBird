# PaperBird — Jira+Confluence 기능 확장 기획 (2026-11-24 재작성)

## 1. 배경 / 컨셉 전환

- 기존: 대학원 랩실 특화 (교수 ↔ 대학원생)
- 신규: **범용 B2B 사내 협업 플랫폼** — 어떤 기업·팀이든 사용하는 사내 전용 서비스
- 핵심 레퍼런스: Atlassian — 유저 인증/권한 관리 + **Jira의 칸반/워크플로우** + **Confluence의 문서 템플릿**
- 기존 AI 핵심 기능(RAG 검색, 요약, PII 마스킹, 리스크 스코어링, LLM-judge)은 그대로 유지. Jira/Confluence 스타일 UI는 전달 방식이지 AI 기능을 대체하는 게 아님

## 2. 작업 방식: 1차(Rea) → 2차(PaperBird 디자인화)

- **1차**: Rea를 사용해 기존 세팅된 기반에서 브랜치를 따서, 아틀라시안 핵심 기능(유저 인증/권한 관리, 컨플루언스 문서 기능, 지라 칸반 기능)을 빠르게 카피·스캐폴딩
- **2차**: 1차 결과물을 PaperBird 컨셉에 맞게 재설계 — 디자인 md 문서를 작성한 뒤 그 기준으로 UI/UX 수정
- [ ] Rea로 작업하는 동안 기존 하네스 규칙(BOUNDARIES.md, SPEC.md 등)을 일부 예외 처리할 가능성 있음 — **내일 오전 팀 논의 후 확정**

## 3. 신규 기능 A: 문서 승인 칸반 (Jira 참고)

- 보드 컬럼(안): 전달됨 → 승인대기 → 승인중 → 승인됨 / 반려
- [ ] 기존 보고서 상태머신(REQUESTED/PENDING_REVIEW/APPROVED/DELIVERED 등)과 일치시킬지, 칸반 전용 상태로 별도 정의할지 확정 필요
- 카드 클릭 시 보고서 상세·히스토리·코멘트 확인

## 4. 신규 기능 B: 보고서 템플릿 (Confluence 참고)

현재 정해진 보고서 유형 4종:
- 진행보고서 (일일 / 주간 / 실패)
- 성과보고서
- 과제보고서
- 연구비 지원기관 보고서

※ 범용 기업 대상 컨셉과 "연구비 지원기관"이라는 명칭이 어긋남 — 일반화 여부 검토 필요

## 5. 신규 기능 C: RAG 챗봇 (우측 패널)

- 화면 우측에 플로팅 버튼 추가 → 클릭 시 챗봇 패널 오픈
- 대화형 질의 예: "그때 이런 내용 보고했던 거 알려줘"
- 응답 구성: 자연어 답변 + 근거로 사용한 문서 링크(복수 가능)
- 링크 클릭 시 해당 문서 상세 페이지로 라우팅
- [ ] 기존에 설계된 RAG 검색 패널(워크스페이스 3분할 레이아웃의 우측 패널)과 역할이 겹침 — 별도 챗봇 UI로 분리할지, 검색 패널을 챗봇 형태로 통합할지 결정 필요

## 6. 타깃 재정의

- 대학원생&교수 → 임의의 기업·팀 (사내 전용 서비스)
- 영향: 역할/권한 모델을 "PI/대학원생" 구조에서 "팀장/팀원/외부 승인자" 같은 범용 구조로 재설계 필요

## 7. 계정/워크스페이스 온보딩 (Atlassian 참고)

가입 → 워크스페이스(회사/팀) 생성 → 팀원 초대 → 역할 배정 전체 플로우. 1차 Rea 작업 범위에 포함.

- [ ] 가입 방식 (이메일/SSO 등)
- [ ] 워크스페이스 생성 플로우
- [ ] 팀원 초대 플로우 (초대 링크, 권한 사전 지정)
- [ ] 역할/권한 템플릿 (팀장/팀원/외부 협업자 등)

## 8. 스킬 변경 필요 사항

- 기존: Jira 티켓명을 읽어서 에이전트에게 작업을 지시하는 스킬 구조
- 변경: **GitHub Projects**의 이슈/카드를 읽어오는 방식으로 전환
- 영향 가능 스킬: `/api-change`, `/deploy-check`, `/threat-check` 등
- [ ] GitHub Projects 연동 방식 결정 (gh CLI vs GraphQL API vs 웹훅)

## 9. 내일 오전 팀 논의 안건

- [ ] Rea 작업 시 하네스 규칙 예외 허용 범위
- [ ] 칸반 상태값 ↔ 보고서 상태머신 매핑
- [ ] 보고서 템플릿 4종 상세 필드 정의
- [ ] RAG 챗봇 vs 기존 검색 패널 통합 여부
- [ ] 와이어프레임 대상 화면 목록 (로그인/가입, 워크스페이스 생성, 칸반 보드, 보고서 작성, RAG 챗봇)
- [ ] GitHub Projects 연동 방식

## 10. 열린 리스크

- 핵심 AI 차별화(RAG·리스크스코어링·LLM-judge)가 Jira/Confluence UI에 묻히지 않도록, 데모 동선에서 AI 기능이 먼저 드러나게 구성할 것
- "연구비 지원기관 보고서" 템플릿 명칭의 일반화 여부
