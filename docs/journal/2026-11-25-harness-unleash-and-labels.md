# Rea 미사용 결정, 목줄 해제 모드, 메인·서브 라벨

- 날짜: 2026-11-25
- 관련: [2026-11-24 Jira+Confluence 기능 확장 기획](2026-11-24-jira-confluence-expansion.md) §2 (Rea 1차 작업 계획)

## 배경

- 기존 계획은 Rea로 Atlassian 핵심 기능을 빠르게 카피·스캐폴딩하고(1차), 그 결과를 PaperBird 디자인으로 다듬는 것(2차)이었다.
- Rea 작업 동안은 하네스 규칙을 일부 예외로 둘 가능성이 회의 안건이었다.

## 결정과 이유

1. **Rea를 쓰지 않는다.**
   - Jira·Confluence를 통째로 카피하면 오히려 걷어낼 것이 많다.
   - 대신 Jira에서 필요한 기능을 목록으로 뽑아 하나씩 요청하는 방식이 낫다고 판단했다.
2. **초반 작업은 Claude에게 직접 맡기되, 하네스 규칙을 일시적으로 푸는 명령을 둔다.**
   - 이름: `/unleash`(해제) · `/leash`(복귀). 팀이 쓰는 "목줄" 표현과 맞고, 복귀 명령이 짝으로 드러나서 풀어 둔 채 잊는 일을 줄인다.
   - 풀리는 규칙과 풀리지 않는 규칙을 루트 `CLAUDE.md` §6에 명시했다. 시크릿, 파괴적 명령, 에이전트 머지, 검사 결과 허위 보고는 풀리지 않는다.
   - 해제 PR은 팀장 리뷰를 받는다.
3. **메인 라벨 1개 + 서브 라벨 0개 이상.**
   - 다른 트랙이 엮인 기능(예: 백엔드 + 보안)은 `fullstack` + `sub:security`처럼 붙이고, 엮이지 않으면 메인 라벨만 붙인다.
   - 서브 라벨이 있으면 그 트랙 경로 수정을 허용하고 그 트랙 리뷰를 받는다.
   - 목줄 해제 티켓에는 적용하지 않는다.

## 결과

- 반영 문서: 루트 `CLAUDE.md` §5·§6, `docs/BOUNDARIES.md` §1·§2·§5, `docs/conventions/PR_STRATEGY.md`, `.github` 템플릿, `.claude/skills/{unleash,leash}`, 기존 스킬(`seq`, `finish`, `verify`, `parallel`)의 라벨 확인 단계
- 불확실: 서브 라벨 트랙 리뷰는 아직 문서·스킬 규칙으로만 지켜진다. CODEOWNERS는 라벨을 보지 못하므로, 강제하려면 GitHub Action이 필요하다.
