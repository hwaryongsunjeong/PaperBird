# 주간 티켓 흐름: 후보(candidate) 생성 → 금요일 팀장 승인

- 날짜: 2026-11-26
- 관련: [docs/conventions/TICKET.md](../conventions/TICKET.md), `/ticket`, `/triage`

## 배경

- 비슷한 작업이 담긴 이슈가 여러 개 생기면 작업 중 파일이 꼬인다.
- 티켓이 주마다 너무 많거나 적어지지 않게 해서 타임라인 데드라인을 지키고, 작업을 한눈에 보고 싶다.
- 팀원은 각자 자기 AI에게 티켓 작성을 맡기므로, 어떤 AI가 만들어도 같은 양식이어야 한다.

## 선택지

- A. 팀원 AI가 주간 취합 이슈에 후보를 댓글로 올림 → 팀장이 일괄 생성
- B. 팀원이 `candidate` 라벨로 후보 이슈를 직접 생성 → 팀장이 금요일에 승인
- C. 팀원이 이슈를 바로 생성 (승인 관문 없음)

## 결정과 이유

**B를 택했다.**
- 원래 목적(중복·충돌 방지, 주간 작업량 조절)은 누가 만드느냐가 아니라 승인 관문이 있느냐로 해결된다.
- 후보도 실제 이슈라서, 다른 사람의 후보까지 실시간으로 비슷한 작업·파일 겹침 검색에 잡힌다. 댓글 방식(A)은 이게 어렵다.
- 팀장은 생성이 아니라 승인만 하므로 금요일 부담이 적다.
- 주중 예외는 두지 않는다. 언제 작업이 생길지 모르므로, 작업 중 생긴 후속 이슈도 모두 `candidate`로 만들고 다음 금요일에 승인받는다.
- 후보 마감은 금요일 16:00.

## 결과

- 양식 원본: `docs/conventions/TICKET.md` (본문 7개 섹션, 제목 규칙, 라벨, 주간 흐름, Draft 카드 금지)
- `/ticket` (팀원, AI 자동 호출 허용 — 생성 전 확인 필수), `/triage` (팀장, 직접 입력만)
- fullstack 작업 스킬(`/seq`, `/parallel`, `/compare`)은 `candidate` 이슈로 시작하지 않는다. 다른 트랙은 이 스킬을 쓰지 않으므로 규칙(루트 CLAUDE.md §5)으로 지킨다.
- 불확실: `/triage` 실행자가 팀장인지는 스킬이 확인할 수 없다 (사람 규칙).
